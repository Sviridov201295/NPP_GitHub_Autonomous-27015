# Syndicate NPP Monitor — автономный опрос GitHub Actions

Это **готовый статический сайт + автоматический опрос публичного Valve A2S** по UDP для `45.12.63.132:27015`.
**Не требуется:** свой компьютер, Render, Firebase, запуск Lua, изменение Garry's Mod-сервера или RCON.
**Ограничение:** штатный A2S не передаёт температуру реактора, износ ТВЭЛов, обороты турбины и аварии АЭС. Эти поля будут пустыми, если сервер не публикует соответствующие публичные данные через `A2S_RULES`. Открытый порт не превращает внутренние Lua-переменные в общедоступные данные.

## Как подключить к существующему репозиторию

1. Распакуйте архив и загрузите **содержимое**, включая скрытую папку `.github`, в корень GitHub-репозитория. Важно: `index.html`, `server-query.js`, `app.js`, `styles.css`, `requirements.txt`, `.github/workflows/a2s-pages.yml`, `scripts/query_server.py` должны быть в указанных путях. Это **заменяет** предыдущий проект GitHub Pages + Firebase.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions** (не `Deploy from a branch`).
3. Перейдите **Actions → A2S monitor → GitHub Pages → Run workflow**. Если Actions не включены, разрешите их в репозитории.
4. Проверьте два этапа `collect` и `deploy`. После успеха откройте адрес в **Settings → Pages → Visit site**. Публичный адрес обычно `https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПО/`.
5. Дальше опрос запланирован на минуты 07, 17, 27, 37, 47, 57 каждого часа UTC, без вашего участия. GitHub может задерживать или пропускать запуски. В публичных репозиториях расписание могут отключить через 60 дней отсутствия активности.

**Важно:** GitHub Pages публикует только файлы сайта. Python выполняется **в GitHub Actions**, а затем обновлённый статический сайт публикуется через `actions/deploy-pages`.

## Что реально получает сайт

- Публичные данные `A2S_INFO`: имя сервера, карта, число игроков, максимум игроков и факт успешного ответа.
- Сводка `A2S_RULES`: число опубликованных правил; отдельные разрешённые поля, если они найдены по конкретным именам: `NC_Station_KW`, `NC_Reserve_KW`, `NC_Reserve_Fuel`, `Syndicate_CityPower_Gen`, `Syndicate_CityPower_Load`, `Syndicate_City_Blackout`, `Syndicate_NPP_Fuel`, `Syndicate_NPP_State`.
- В поле «Генерация АЭС» попадёт **только** числовое значение публичного `NC_Station_KW`; «Потребление» — только `Syndicate_CityPower_Load`, резерв — `NC_Reserve_KW`. Остальные публичные значения представлены как исходные ключи и значения, без домыслов о единицах.
- Если сервер не возвращает A2S_INFO или A2S_RULES, сайт честно покажет отсутствие подтверждённых данных. Если GitHub Actions перестанет обновлять сайт, последние результаты отметятся как устаревшие спустя 30 минут.
- Опрос 1 раз в 10 минут; это **не мониторинг в реальном времени с частотой 2 секунды**.

## Проверка и отладка

- В браузере откройте `?demo=1`: только для проверки интерфейса, явно подставляются искусственные значения.
- Для юнит-тестов выполните `python -m unittest discover -s tests -v` (Python 3.9+).
- Для локального публичного запроса выполните `pip install -r requirements.txt`, затем `python scripts/query_server.py --output site/data/source-query.json`. При UDP-тайм-ауте скрипт завершится успешно и напишет ошибку в JSON, чтобы сайт мог вывести достоверное состояние.
- Если сервер доступен по игровому порту, но A2S не отвечает, причиной могут быть фильтрация UDP, защита от запросов или отдельный query-порт. Без подтверждения не перебирайте порты.

## Почему нельзя получить всю АЭС по открытому порту

Из предыдущих Lua-файлов: показатели АЭС передаются игровому клиенту через собственное сетевое сообщение `synd_phone_npp_state`. Для получения этих сообщений недостаточно одного запроса Valve A2S — нужна полноценная игровая сессия с доступом к сводке либо другой опубликованный сервером интерфейс.

Этот проект **не использует** RCON, не выполняет консольные команды, не пытается обойти проверку роли, античит или `sv_allowcslua 0`. Для полной автономной телеметрии АЭС при отсутствии публичных полей серверу нужен уже существующий публичный API, доступная авторизованная телеметрия или согласованная серверная интеграция. Иначе обещать точные показатели невозможно.

## Технические файлы

- `index.html`, `styles.css`, `app.js`, `server-query.js` — статическая страница и индикаторы.
- `.github/workflows/a2s-pages.yml` — расписание, сбор данных, публикация GitHub Pages.
- `scripts/query_server.py` — ограниченные публичные UDP-запросы с тайм-аутом 5 секунд.
- `requirements.txt` — `python-a2s==1.4.2`.
- `tests/test_query_server.py` — тестирование без сетевого подключения.
- `data/source-query.json` — в опубликованном сайте автоматически создаваемая сводка проверки.

**Статус проверки в данном окружении:** UDP-запрос к `45.12.63.132:27015` завершился тайм-аутом. Доступность из среды GitHub Actions отдельно не проверялась.
